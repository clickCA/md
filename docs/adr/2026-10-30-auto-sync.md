# ADR: Auto-sync when the app is active

Date: 2026-10-30
Status: accepted
Scope: md-app UI (useVault), sync engine contract

## Context

The product promise is "immediate sync when the app is active; opportunistic
on mobile" — but until now nothing in the UI actually triggered a sync after
edits; the user had to press the sync button. The sync engine itself is
already journaled and idempotent (re-running after a kill at any state
converges), so *repeating* sync is safe by construction. What was missing was
policy: when may the UI fire it without asking, and how loudly may it fail?

## Decision

1. **Triggers.** After every note mutation (write, create, delete, move) a
   debounced timer schedules a sync 5 seconds after the last change. When the
   window becomes visible again (refocus, un-minimize), a sync runs
   immediately. A pending timer never leaks across vault switches.
2. **Guards.** Auto-sync fires only when: a remote is configured, auto-sync
   is enabled, the vault is open, no sync is already running, and the window
   is visible. Local-only vaults never touch the network.
3. **Silent failure.** Auto-sync never opens the credentials dialog and never
   sets the global error banner — it must not nag. Failures land in a
   `lastSyncError` surfaced inside the git panel ("background sync failed —
   …"), cleared on the next successful sync. Auth failures are silent too:
   the manual sync button and its dialog remain the way to sign in.
4. **User override.** Vault settings has an "auto-sync when a remote is set"
   checkbox (default on), persisted in `localStorage` (`quire.autosync`).
5. **No protocol changes.** Auto-sync calls the same `vault_sync` command as
   the button. Conflict handling is unchanged: overlapping edits still produce
   conflict copies; auto-sync never auto-resolves.

## Consequences

- The README's sync promise is now actually implemented on desktop.
- A flaky network shows as a small red note in the source-control panel, not
  as an interruption — the user keeps editing; the next trigger retries.
- Auto-sync only ever *adds* sync attempts to a safe engine; if a future
  engine bug appears, disabling the checkbox reverts to fully manual sync
  without code changes.

## Out of scope (deliberate)

Mobile background scheduling (OS-dependent, MOB phase), push-on-interval
timers independent of user activity, and any auto-resolution of conflicts.
